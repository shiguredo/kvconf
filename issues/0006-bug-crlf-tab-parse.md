# CRLF の空行とタブインデントのコメント行を parse できるようにする

- Created: 2026-07-31
- Completed: YYYY-MM-DD
- Branch: feature/fix-crlf-tab-parse
- Polished: 2026-07-31

## 目的

コメント・空白行の判定正規表現が \r と \t を処理しないため、CRLF 改行の設定ファイルの空行、およびタブインデントのコメント行が正しくスキップされない（invalid_line_format になる、または設定に誤受理される）。正しくスキップする。

## 現状

- src/kvconf.erl の parse_lines の re:run(Line, <<"^ *(#.*)?$">>) はスペースのみ許容する
- 実測: initialize([], <<"a = 1\r\n\r\n">>) は {error, {invalid_line_format, <<"\r">>, 2}} になり、initialize([], <<"\t# comment\n">>) も同様にエラーになる
- タブのみの行（<<"\t">>）やスペース + CR の空白行（<<" \r">>）も同じ原因でエラーになる
- タブインデントのコメント行で = を含むもの（<<"\t# comment = foo">>）は invalid_line_format にならず、キー "# comment" として設定に誤受理される。実測: initialize([], <<"\t# comment = foo\n">>) は {ok, [<<"# comment">>], []} になる
- 値行は string:trim が \r を除去するため通るが、空行だけ非対称に失敗する
- CRLF のコメント行（<<"# comment\r">>）は "#.*" が \r を吸収するため既に通る
- タブインデントの値行（<<"\ta = 1">>）は string:trim が \t を除去するため既に通る
- 0001 は parse_lines の string:trim の例外エラー返却化を、0010 はキー行の空キー判定を担当する。本 issue はコメント・空白行判定の正規表現のみを対象とする

## 設計方針

- コメント・空白行の正規表現を ^[ \t\r]*(#.*)?$ の形に拡張する（行頭のスペース・タブ・\r と行末の \r を許容する）
- 値行の判定（^([^=]*)=(.*)$）と string:trim は変更しない

## 完了条件

- CRLF の空行（\r のみ、スペース + CR、タブ + CR を含む）がスキップされる
- タブインデントのコメント行とタブのみの空行がスキップされる
- タブインデントのコメント行で = を含むものが設定に誤受理されない
- CRLF のコメント行 / スペースインデントのコメント行 / CRLF の値行 / タブインデントの値行が引き続き受理される（回帰テスト）
- 回帰テストが kvconf.erl 内の eunit に追加されている
